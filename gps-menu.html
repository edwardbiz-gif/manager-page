Key design decisions — approve or edit
Decisioncore design

Tap-in / tap-out + server-side geofence

No web background geolocation exists on iOS or Android, so auto-arrival is impossible. Keep explicit one-tap check-in with the geofence enforced server-side (already correct in v65) + 4h auto-close safety net.

Decisioncore design

Guided + skippable check-out

On check-out, each flagged item (critical / near-due / stale task, overdue, open complaint) must be actioned with a note OR skipped with a reason. Turns the manual step into the visit record.

Decisioncore design

Consent gate + 90-day coordinate purge

Versioned GPS consent before any check-in writes; raw lat/lng purged after ~90 days (keep derived duration/distance). BIPA excludes GPS; this is the clean legal posture.

Decisioncore design

Live shift + real-time labor = Phase-2 (LifeLenz)

Paycor is empty and R365 labor lags ~2 days, so "who is on shift right now" is not possible today. Phase-1 shows a date-stamped recent-day R365 curve + a 1-tap "who is here" confirm; true real-time waits on a LifeLenz feed.

Decisioncore design

Flexible visit capture

Visit notes/photos/checklist kept deliberately loose (kind = note | photo | checklist_item) so the mix can evolve without schema churn.
